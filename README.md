# 경북대학교 세포·기질연구소 천연나노융합사업단(N2C) 홈페이지

2026 교육부 글로컬랩(거점형) 천연나노융합사업단(N2C, Natural Nano Convergence Center)의 홈페이지예요. GitHub Pages로 열고, 관리자가 공지·세미나·소식과 구성원 명단을 올리고, 공모 프로그램 신청을 로그인 없이 받고, 사업 보고에 쓸 교수님별 성과를 개인 링크로 모아요. 레이아웃과 디자인은 세포·기질연구소 홈페이지([kkonoo/cmri](https://github.com/kkonoo/cmri))와 같아요.

- 홈페이지: https://kkonoo.github.io/n2c/
- 관리자: https://kkonoo.github.io/n2c/admin.html

| 관리자 → 관리자 | 관리자 추가·빼기 (구글 계정) |

- **한국어/영어**: 오른쪽 위 `EN`/`KO` 버튼. 처음에는 브라우저 언어를 따라요(한국어가 아니면 영어). 관리자가 쓴 글은 쓴 그대로 보여요.
- **밝은/어두운 화면**: 오른쪽 위 달·해 버튼. 처음에는 기기 설정을 따라요.
- 고른 값은 이 브라우저에 저장돼요(`n2c-prefs`).
- 공지 분류를 **모집**으로 쓰면 공모·신청 → 모집 공고에도 나와요.
- 사업단 소식에 사진 주소(.jpg·.png)를 첨부 링크로 넣으면 첫 사진이 메인 카드에 나와요.
- 구성원: 모두 관리자 화면의 구성원 탭에서 관리해요. 그룹을 정한 사람은 사업단 소개 → 구성원에 그룹별로(책임 → 공동 → 참여) 먼저 나오고, 이름 앞에 역할 칩(책임 파랑·공동 주황·참여 회색)이 붙어요. 나머지는 구분별로 나와요. 명단이 비어 있으면 ‘준비 중’ 안내가 보여요.
- **세포·기질연구소 명단 가져오기**(`data/cmri-members.json`, 2026년 11월 기준): 구성원이 하나도 없을 때 누르면 CMRI 홈페이지의 참여교수 50명·연구초빙교수 20명(사진 포함)과 그룹을 정해 둔 사업단 연구진 11명을 넣어요. 이미 명단이 있으면 지운 분이 다시 들어오지 않게 그룹 연구진만 봐요 — 없는 분은 넣고, 그룹이 비어 있는 분은 그룹·역할을 채워요. CMRI 명단에 없던 박홍식·이금비·강지연·강경구·심만규 다섯 분의 사진은 발표 자료에서 잘라 넣었고, 사진이 비어 있으면 가져오기가 채워요.
- 구성원 순서: 한 묶음(그룹·구분) 안에서 책임 → 공동 → 참여, 그다음 관리자가 정한 순서 칸의 숫자(작은 숫자 먼저, 비우면 자동), 그다음 구분(참여교수 → 연구초빙교수 → … → 연구원), 그다음 가나다순이에요.
- 성과: 실적은 관리자 페이지 성과 탭에서만 모아 볼 수 있어요. 교수님마다 링크를 보내면(링크 모두 복사 → 엑셀에 붙여 메일 병합) 교수님은 그 링크로 자기 실적만 넣고 고쳐요. 링크를 가진 사람은 그 교수님 실적을 고칠 수 있으니 새어 나가면 **새 링크**로 바꿔요(예전 링크는 바로 막혀요). 관리자가 **열기**로 들어가면 관리자 권한으로 대신 넣거나 고쳐요. 항목과 칸은 [`js/report-types.js`](js/report-types.js)에서 바꿔요(항목을 더하면 `firestore.rules`의 `cat` 목록도 함께). 기간은 연·월로 골라요(연차가 3월–다음 해 2월이라 예: 1차년도는 2026년 9월 ~ 2027년 2월). 인력양성은 입학·임용 ~ 졸업·끝이 기간과 겹치면 들어가고, 나머지는 각 실적의 날짜(논문은 게재 연월, 글로벌 교류는 시작 연월)로 기간에 넣어요.
- 정량성과 14개 항목 산정 기준 (`KPIS`, [`js/report-types.js`](js/report-types.js)). 협의회 공통 기준이 나오면 여기만 고쳐요.

  | 항목 | 세는 법 |
  |---|---|
  | 상위 10% 이내 논문 | 학술지 논문 중 교수님이 적은 JCR 상위 %가 10 이하 |
  | 최우수학회 논문 | 논문 구분이 ‘학술대회 (최우수학회)’ |
  | 학술대회·세미나 개최 | 개최한 행사 수 |
  | 국내 특허 / 해외 특허 | 출원과 등록을 모두 1건씩 (PCT는 해외) |
  | 학문후속세대 양성 | 박사후연구원·신진연구자, 참여 기간이 겹치는 해마다 1건 |
  | 대학원생 지원 | 석사·박사·석박통합, 참여 기간이 겹치는 해마다 1건 |
  | 교육인원 | 교육 프로그램 교육 인원의 합 (명) |
  | 글로벌 교류 / 기업 지원 | 넣은 수 |
  | 거점 인프라 활용 | 이용 건수의 합 (비우면 1건) |
  | 기술이전 / 경제적 파급효과 | 기술료·금액(천원)의 합 ÷ 100,000 = 억원, 소수 첫째 자리 |
  | 고용창출 효과 | 고용 인원의 합 (명) |

- 정량성과 양식 받기: [`data/kpi-form.xlsx`](data/kpi-form.xlsx)·[`data/kpi-form.pptx`](data/kpi-form.pptx)(협의회 양식 원본)를 열어 값만 채워 받아요. 서식·수식·다른 시트는 그대로예요. 고른 기간을 사업연도(3월 ~ 다음 해 2월)로 나눠 엑셀 사업단입력 시트의 연도 열(2026년 = 2026.03 ~ 2027.02)에 넣고, 끝 달이 든 해를 기준연도로 해요. 기간에 들지 않는 해는 빈칸(미조사)이에요. 파워포인트는 1쪽에 기준연도 값, 2쪽에 최근 4년 표(2026년 전은 “-”)를 채워요. 양식이 바뀌면 같은 이름으로 파일을 바꿔 넣으면 되는데, 엑셀 7–20행·D–M열과 파워포인트 ‘값_…’ 상자 이름이 그대로여야 해요. 파일을 만들 때 JSZip(cdnjs)을 불러와요.
- 공모·신청: 메일 발송 기능이 없어서 새 신청 알림 메일과 결과 메일은 나가지 않아요. 관리자 탭의 건수로 확인하고, 결과는 신청을 열어 이메일을 누르면 열리는 메일 쓰기 창이나 전화로 알려요. 로그인 없이 받아서 이름·이메일은 확인되지 않은 값이에요. 종류와 칸은 [`js/apply-types.js`](js/apply-types.js)에서 바꿔요(종류를 더하면 `firestore.rules`의 목록도 함께).

## 처음 설정 (한 번만)

Firebase 프로젝트 `nc2-knu`의 웹 앱 설정값은 이미 [`js/firebase-config.js`](js/firebase-config.js)에 들어 있어요. 콘솔(https://console.firebase.google.com → `nc2-knu`)에서 아래만 하면 돼요.

1. **Authentication** → 시작하기 → 로그인 방법에서 **Google** 사용, 성과 입력 링크를 쓰려면 **익명**도 사용. 설정 → 승인된 도메인에 `kkonoo.github.io` 추가.
2. **Firestore Database** → 데이터베이스 만들기 → 위치 **asia-northeast3 (서울)**, 프로덕션 모드.
3. Firestore → 규칙 탭에 [`firestore.rules`](firestore.rules) 내용을 그대로 붙여 넣고 **게시**. 규칙 파일이 바뀌면(구성원 구분, 공모·신청, 성과 입력이 더해질 때처럼) 다시 붙여 넣고 게시해요.
4. 첫 관리자 등록: Firestore → 데이터 → 컬렉션 시작 `admins` → 문서 ID에 관리자 구글 이메일(소문자, 예: `hong@gmail.com`) → 필드 아무거나 하나(예: `name` = 홍길동). 나머지 관리자는 관리자 페이지 → 관리자 탭에서 추가하면 돼요.
5. **Storage**(공모·신청 첨부 파일) → 시작하기 → 위치 `asia-northeast3`. 새 프로젝트는 **Blaze(종량제)** 요금제여야 Storage를 켤 수 있어요(프로젝트 개요 → 업그레이드, 결제 카드 등록). 신청 첨부 파일 정도는 보통 한 달 몇십 원 수준이고, Google Cloud 콘솔 → 결제 → 예산 및 알림에서 월 1만 원 같은 알림을 걸어 두면 안심이에요.
6. Storage → 규칙 탭에 [`storage.rules`](storage.rules)를 붙여 넣고 **게시**. Firestore의 관리자·신청서를 확인하는 규칙이라 Firestore 접근 권한을 묻는 창이 뜨면 허용해요.
7. GitHub 저장소 Settings → Pages → Source: Deploy from a branch → `main` / `(root)`.
8. 관리자 페이지 → 구성원 → **세포·기질연구소 명단 가져오기**.

Firestore를 만들기 전에는 메인과 게시판에 ‘글을 불러오지 못했어요’가 보여요. Storage를 켜기 전에도 첨부 파일 없는 신청은 받아요. 규칙은 Firebase CLI로도 올릴 수 있어요: `firebase deploy --only firestore:rules,storage` (프로젝트는 [`.firebaserc`](.firebaserc)의 `nc2-knu`).

## 데이터는 어디에

모두 Firestore와 Storage에 있고, 누가 읽고 쓸 수 있는지는 [`firestore.rules`](firestore.rules)와 [`storage.rules`](storage.rules)가 정해요.

| 컬렉션 | 내용 | 읽기 | 쓰기 |
| --- | --- | --- | --- |
| `notices`, `seminars`, `news` | 게시글 (`seminars`가 세미나·워크숍 게시판) | 누구나 | 관리자 |
| `members` | 구성원 명단 (이메일도 공개돼요) | 누구나 | 관리자 |
| `applications` | 공모·신청 | 관리자 | 누구나 새로 내기만(로그인 없음), 관리자는 결과·메모·삭제만 |
| `admins` | 관리자 (문서 ID = 이메일) | 관리자 | 관리자 |
| `reporters` | 성과 입력 교수님 명단 (이름·소속·지금 링크 토큰) | 관리자 | 관리자 |
| `reportKeys` | 개인 링크 토큰 → 교수님 (문서 ID = 토큰) | 토큰을 아는 사람만 한 건씩, 목록은 관리자 | 관리자 |
| `reportSessions` | 링크로 들어온 익명 접속이 쓰는 토큰 (문서 ID = 익명 uid) | 본인 | 본인(있는 토큰만) |
| `reports` | 교수님별 실적 (항목 `cat`, 칸 `f`) | 관리자, 그 교수님 링크 | 관리자, 그 교수님 링크 |
| Storage `applications/{신청}/` | 신청 첨부 파일 (20MB, 한글·PDF·사진 등) | 관리자 | 신청서에 적힌 파일만 신청하고 1시간 안에 올리기, 관리자는 지우기 |

## 글 고치기

- 한 페이지 안에 한국어와 영어가 함께 있어요. `<span lang="ko">한국어</span><span lang="en">English</span>`처럼 짝으로 쓰면 고른 언어만 보여요. 긴 문단은 `<p lang="ko">`, `<p lang="en">`로 나눠요.
- 위쪽 메뉴와 푸터는 모든 공개 페이지(`index`, `about`, `research`, `programs`, `apply`, `board`, `post`)에 똑같이 들어 있어요. 메뉴나 연락처를 바꿀 때는 일곱 파일을 함께 고쳐요.
- 색은 `css/style.css` 맨 위 `:root`(밝은 화면)와 바로 아래 어두운 화면 블록에서 바꿔요. 지금은 세포·기질연구소 홈페이지와 같은 파랑·주황이에요.
